# Factory 内容管理器实施计划

日期：2026-11-01。状态：待实施。

## 目标与范围

在 Unity 编辑器内增加 `Factory > 内容管理器`，以“建筑、物品、配方”三个页签管理游戏内容，接入 Blender 插件导出的 `.factory.json` 和 FBX。

实施顺序：**数据读写基础 → 物品与配方管理 → 建筑管理及 JSON 导入 → FBX 导入与材质适配 → 联调**。

保持轻量：复用现有 CSV 导入器、数据库校验、图标烘焙和 Unity 模型导入机制。只做影响数据可用性的检查，不建设通用数据框架、哈希追踪、自动同步服务或完整资产流水线。

## 数据职责

| 数据 | 编辑源及规则 |
|---|---|
| 建筑、物品、配方配置 | `Assets/Data/FactoryTables` 中的 CSV，管理器负责读写 |
| 运行时数据库 | `Assets/Data/Generated/FactoryDatabase.asset`，继续作为生成缓存，不直接编辑 |
| 占格、端口 | JSON 提供初始数据；允许在 Unity 修改并保存至 CSV |
| 模型和纹理 | FBX 与图片资产，交由 Unity 原生导入器处理 |
| 最终材质 | Unity `.mat`，保存源材质到 Unity 材质的映射 |
| 碰撞代理 | JSON 提供参数，保存到建筑导入配置，再生成代理与碰撞数据 |
| 建筑导入配置 | 每个建筑一个小型 Editor 配置资产，保存模型引用、碰撞代理和必要导入设置；不复制名称、占格、端口等 CSV 字段 |

建筑以 Key 关联，文件名只用于寻找模型。新增和更新使用同一个入口；不新增第二套建筑或配方数据库。

## 阶段一：数据读写基础

- [ ] 从 `FactoryDatabaseCsvImporter` 中提取可复用的读取、候选数据校验和生成入口，保留现有重建菜单。
- [ ] 增加针对现有表的 CSV 写入能力，正确处理逗号、引号、换行和中文，不引入通用 ORM。
- [ ] 编辑器使用内存草稿，提供保存、放弃修改和未保存提示；撤销/重做作用于草稿。
- [ ] 保存前使用现有校验检查整组候选数据；成功后写入相关 CSV 并重建数据库。
- [ ] 多表保存期间暂缓自动重建，结束后只重建一次。写入失败时恢复本次涉及的旧文本，提示具体文件；不建设长期备份系统。
- [ ] Play Mode 中禁用内容写入，避免修改运行中的 ID 和烘焙数据。

保留其他建筑、其他语言名称和无关数据行。列表排序只影响显示，不改变源表行序；现有建筑数字 ID 按行序生成，不额外重排。

验收：修改一个字段、保存、重建后可正确读回；非法修改不会覆盖有效数据库。

## 阶段二：物品与配方页签

窗口采用 UI Toolkit，顶部三个页签；每页共享搜索、新增、删除、保存操作，左侧列表、右侧详情。无需多窗口或独立应用。

### 物品

- [ ] 列表显示图标、Key 和名称，支持按 Key/名称搜索。
- [ ] 详情展示所有现有属性：ID、Key、名称字段、最大堆叠、分类、Prefab 和图标绑定。
- [ ] 支持新增、删除、修改；新增时提供空闲 ID，允许手动修改但检查唯一性。
- [ ] Prefab 和图标使用资产选择框，保存时转换为现有表使用的 Key；第一版遵守现有资产目录和命名规则。
- [ ] 修改物品 Key 时同步更新配方引用；被配方引用的物品暂不允许直接删除，列出引用以便先处理。
- [ ] 降低最大堆叠时，提示数量超限的配方，不自动改动配方数量。

名称沿用现有 `name_key` 语义；本期不引入完整本地化系统。

### 配方

- [ ] 列表显示原料和产物的图标、数量，以及 Key、加工类型和生产时间。
- [ ] 支持配方新增、删除和属性编辑。
- [ ] 原料与产物使用可编辑条目列表，支持更换物品、修改数量、添加和移除。
- [ ] 添加或更换物品使用带输入搜索的下拉弹窗，显示图标、名称和 Key。
- [ ] 同侧不重复添加同一物品；重复选择时合并数量并检查堆叠上限。
- [ ] 产物明确显示槽位序号，支持上下移动，按该顺序写入 `recipe_outputs.csv`；不能自动按名称排序。
- [ ] 加工类型在详情中提供简单的选择/新增入口，共用 `machine_types.csv`，不增加第四个页签。

复用现有规则：数量为正且不超过最大堆叠，耗时为正，至少一个产物；允许零原料的采矿配方。产物槽必须能被对应加工建筑的输出口覆盖。

验收：完成一次物品新增、配方引用、更改数量与产物排序、保存重开；搜索下拉可正常选择物品。

## 阶段三：建筑页签与 factory.json 导入

### 建筑展示与编辑

- [ ] 列表显示图标、只读 Key、名称、占格及端口缩略图。
- [ ] 点击缩略图，在详情区展开二维网格编辑器：修改占用格、添加/选择/删除/反转端口，并编辑输出产物槽。
- [ ] 沿用 Blender 的占格坐标、端口边界和方向规则，复用 `FactoryBuildingFootprintUtility` 校验。
- [ ] 名称保存到 `building_names.csv`，默认编辑 `zh-CN`，保留其他语言；图标绑定保存到表现表，复用已有图标烘焙入口。
- [ ] 详情中配置 JSON 未提供的行为、加工类型、仓储容量、传送带 Tier/速度及坡度等；只显示对应行为需要的字段。
- [ ] 删除建筑时删除其相关 CSV 行；默认保留 FBX、材质、纹理和 Prefab，避免误删共享资产。

### JSON 导入

- [ ] 在建筑页提供“导入 .factory.json”文件选择入口；第一版先支持单文件。
- [ ] 用明确的 DTO 读取当前 `schema_version = 1`，保留“字段缺失”和“数组为空”的区别，不在运行时增加 JSON 依赖。
- [ ] 按 `building.key` 新增草稿或更新已有建筑，展示占格、端口、碰撞代理三个导入选项及简要预览。
- [ ] 未包含的部分不更新；存在的空数组表示清空该部分；更新已有建筑时保留名称、图标和游戏属性。
- [ ] 对 Unity 中已编辑过的空间数据，不自动覆盖；由用户在本次导入勾选需要覆盖的部分。不比较哈希，不做复杂三方合并。
- [ ] 新增建筑缺少必需占格、行为或 Prefab 时保留为未保存草稿，补齐后再提交，不向 CSV 写入无效条目。
- [ ] Processor 输出口沿用 JSON 的产物槽绑定，非 Processor 清除不适用的 `number/output_slot`。
- [ ] 碰撞代理写入建筑导入配置，供下一阶段生成；JSON 中已转换为 Unity 局部坐标，不再次交换轴。

此阶段可以选择已有 `.prefab` 完成建筑保存，不依赖 FBX 自动生成先完成。

验收：完整 JSON 新增建筑；部分 JSON 只更新选中部分；Unity 修改名称/占格后再次导入，保留未选择覆盖的数据。

## 阶段四：FBX 导入与材质适配

### 模型与 Prefab

- [ ] 建筑详情增加 FBX 选择与“生成/更新 Prefab”入口；先尝试按 JSON 的 `model_file` 寻找配对文件，找不到时手动选择。
- [ ] 外部模型复制到建筑对应的项目目录，纹理一并导入；已在项目内的 FBX 直接引用，不额外复制。
- [ ] 使用 `ModelImporter` 的固定设置约定单位、轴向、动画和材质导入行为，避免每个建筑各自调整。
- [ ] 使用一个非对称样例确认 FBX 与 JSON 的尺寸、朝向和底面中心原点一致，再固定导出/导入预设；不靠模型包围盒自动猜测原点。
- [ ] 创建普通包装 Prefab：根节点保持单位变换，子节点承载 FBX 模型与生成碰撞体；建筑表引用包装 Prefab。
- [ ] 更新时保留既有资产路径和 `.meta`，只更新工具负责的模型/碰撞子节点，不删除重建整套资产。

建议模型位于 `Assets/Art/Buildings/<key>/`，包装 Prefab 位于 `Assets/Prefabs/Buildings/`，沿用项目现有目录风格。

### 材质

- [ ] 列出 FBX 源材质，优先在约定材质目录按名称匹配；重名时手动选择，不全项目模糊匹配。
- [ ] 允许用户选择已有 `.mat`，利用 Unity 模型导入器的材质重映射保存引用。
- [ ] 未匹配时可创建 URP/Lit 材质，简单承接颜色及可识别的贴图；复杂 Blender 节点不自动翻译。
- [ ] 材质适配界面支持指定基础色、法线、金属度/光滑度、发光与透明设置。粗糙度转光滑度或通道不兼容时明确提示；首版不实现通用纹理打包器。
- [ ] 源材质映射按“FBX 资产 + 源材质名称”维护，不只依赖槽位序号；源材质改名或新增时提示重新匹配。
- [ ] 再导入模型时保留现有 `.mat` 和人工调整，不重复提取、创建或覆盖共享材质。

美术交付约定：模型、UV、稳定的材质分区名称；需要独特外观时交付图片贴图。最终 Shader 和渲染效果在 Unity 配置。

### 碰撞代理接入

- [ ] 从建筑导入配置生成 Box、Sphere、Capsule 及 Cylinder 对应的碰撞数据，位置、旋转、尺寸按 JSON 使用。
- [ ] Unity 普通 Collider 没有圆柱体：需明确使用项目 DOTS Physics 的圆柱形状或简单凸网格，不能替换成胶囊而悄悄改变外形。
- [ ] 调整当前仅允许表现组件的 Prefab 校验，为工具生成的碰撞节点提供明确支持。
- [ ] 接入现有建筑实体生成和拆除流程，确保碰撞跟随建筑放置旋转、楼层及生命周期；仅让 Prefab 显示代理不算完成碰撞。
- [ ] 复用现有 Physics/烘焙机制；只添加必要的建筑碰撞配置，避免新建通用碰撞框架。

验收：一个建筑完成 FBX + JSON 导入、材质匹配、Prefab 生成；替换 FBX 后材质仍正确；游戏内放置、旋转和拆除时碰撞正确。

## 必要检查与验收边界

只保留必需检查：文件可读取、协议版本、重复 Key/ID、必填引用、正数数量/耗时/尺寸，以及现有占格/端口/产物槽规则。错误在当前条目显示，并复用现有数据库校验，不复制整套规则或引入 JSON Schema 校验引擎。

验证以以上各阶段的少量操作验收为主。必要时仅为容易误读的 JSON 部分导入和 CSV 转义补少量自动化用例；不做全组合测试、哈希比对、压力测试或独立测试基础设施。

本期不包含：运行时热更新、存档迁移、完整多语言系统、资源自动监控同步、批量材质节点转换、通用资产依赖管理。现有数字 ID 机制保持不变，Key 用于源数据关联。
