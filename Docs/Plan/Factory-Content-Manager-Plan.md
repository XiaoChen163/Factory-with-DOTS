# Factory 内容管理器实施计划

日期：2026-11-01。状态：阶段一至四已完成（阶段四：2026-11-03）。

## 目标与范围

在 Unity 编辑器内增加 `Factory > 内容管理器`，以“建筑、物品、配方”三个页签管理游戏内容，接入 Blender 插件导出的 `.factory.json` 和 FBX。

blender插件工程位于 `D:\UnityProject\Factory-with-DOTS-BuildingCreater` 下，可以查看相关源码实现，`.factory.json`的数据格式说明也在其中。

实施顺序：**数据读写基础 → 物品与配方管理 → 建筑管理及 JSON 导入 → FBX 导入与材质适配 → 联调**。

保持轻量：复用现有 CSV 导入器、数据库校验、图标烘焙和 Unity 模型导入机制。只做影响数据可用性的检查，不建设通用数据框架、哈希追踪、自动同步服务或完整资产流水线。

## 数据职责

| 数据 | 编辑源及规则 |
|---|---|
| 建筑、物品、配方配置 | `Assets/Data/FactoryTables` 中的 CSV，管理器负责读写 |
| 运行时数据库 | `Assets/Data/Generated/FactoryDatabase.asset`，继续作为生成缓存，不直接编辑 |
| 占格、端口 | 由 Blender 插件导出的 JSON 或 CSV 提供；Unity 内容管理器只读展示，导入时按勾选更新 CSV |
| 模型和纹理 | FBX 与图片资产，交由 Unity 原生导入器处理 |
| 最终材质 | Unity `.mat`，保存源材质到 Unity 材质的映射 |
| 碰撞代理 | JSON 提供参数，保存到建筑导入配置，再生成代理与碰撞数据 |
| 建筑导入配置 | 每个建筑一个小型 Editor 配置资产，保存模型引用、碰撞代理和必要导入设置；不复制名称、占格、端口等 CSV 字段 |

建筑以 Key 关联，文件名只用于寻找模型。新增和更新使用同一个入口；不新增第二套建筑或配方数据库。

## 阶段一：数据读写基础

- [x] 从 `FactoryDatabaseCsvImporter` 中提取可复用的读取、候选数据校验和生成入口，保留现有重建菜单。
- [x] 增加针对现有表的 CSV 写入能力，正确处理逗号、引号、换行和中文，不引入通用 ORM。
- [x] 编辑器使用内存草稿，提供保存、放弃修改和未保存提示；撤销/重做作用于草稿。
- [x] 保存前使用现有校验检查整组候选数据；成功后写入相关 CSV 并重建数据库。
- [x] 多表保存期间暂缓自动重建，结束后只重建一次。写入失败时恢复本次涉及的旧文本，提示具体文件；不建设长期备份系统。
- [x] Play Mode 中禁用内容写入，避免修改运行中的 ID 和烘焙数据。

保留其他建筑、其他语言名称和无关数据行。列表排序只影响显示，不改变源表行序；现有建筑数字 ID 按行序生成，不额外重排。

验收：修改一个字段、保存、重建后可正确读回；非法修改不会覆盖有效数据库。

实施记录（2026-11-02）：提供 UI Toolkit 源表草稿窗口 `Factory > 内容管理器`，复用 `ReadCandidate/Generate`；按记录保留 CSV 未修改内容，事务写入失败恢复原始字节。源表外部变更会阻止保存。使用方式见[内容管理器指南](../Guide/Factory-Content-Manager.md)。

验证：Unity 6000.3.19f1 完整 `Factory.Tests` EditMode 测试通过（314/314），其中内容编辑专项 10 项；覆盖 CSV 转义、窗口未保存状态、撤销/重做、放弃、实际多表保存与数据库重建读回、非法草稿保护、写入失败回滚。测试日志与 XML 位于本地 `Logs/content-manager-tests-final.*`。完整测试需启用图形设备，无图形模式下现有场景测试会触发 Entities Graphics 空引用。

## 阶段二：物品与配方页签

窗口采用 UI Toolkit，顶部三个页签；每页共享搜索、新增、删除、保存操作，左侧列表、右侧详情。无需多窗口或独立应用。

### 物品

- [x] 列表显示图标、Key 和名称，支持按 Key/名称搜索。
- [x] 详情展示所有现有属性：ID、Key、名称字段、最大堆叠、分类、Prefab 和图标绑定。
- [x] 支持新增、删除、修改；新增时提供空闲 ID，允许手动修改但检查唯一性。
- [x] Prefab 和图标使用资产选择框，保存时转换为现有表使用的 Key；第一版遵守现有资产目录和命名规则。
- [x] 修改物品 Key 时同步更新配方引用；被配方引用的物品暂不允许直接删除，列出引用以便先处理。
- [x] 降低最大堆叠时，提示数量超限的配方，不自动改动配方数量。

名称沿用现有 `name_key` 语义；本期不引入完整本地化系统。

### 配方

- [x] 列表显示原料和产物的图标、数量，以及 Key、加工类型和生产时间。
- [x] 支持配方新增、删除和属性编辑。
- [x] 原料与产物使用可编辑条目列表，支持更换物品、修改数量、添加和移除。
- [x] 添加或更换物品使用带输入搜索的下拉弹窗，显示图标、名称和 Key。
- [x] 同侧不重复添加同一物品；重复选择时合并数量并检查堆叠上限。
- [x] 产物明确显示槽位序号，支持上下移动，按该顺序写入 `recipe_outputs.csv`；不能自动按名称排序。
- [x] 加工类型在详情中提供简单的选择/新增入口，共用 `machine_types.csv`，不增加第四个页签。

复用现有规则：数量为正且不超过最大堆叠，耗时为正，至少一个产物；允许零原料的采矿配方。产物槽必须能被对应加工建筑的输出口覆盖。

验收：完成一次物品新增、配方引用、更改数量与产物排序、保存重开；搜索下拉可正常选择物品。

实施记录（2026-11-02）：窗口提供建筑、物品、配方三个页签；物品与配方使用搜索列表和详情编辑，建筑页保留阶段一的源表入口。新增物品分配空闲 ID；资产选择沿用现有目录及文件名 Key，按需补充可选 `icon_key` 列。物品和配方改名同步相关引用，引用中的物品禁止删除；降低堆叠保留数量并列出超限配方。条目支持搜索选择、同侧合并、数量编辑与删除，产物按一基槽位上下移动；加工类型在配方详情新增并写回原表。所有操作继续使用同一草稿、保存事务和候选校验。

验证：Unity 6000.3.19f1 完整 `Factory.Tests` EditMode 测试通过（319/319）。新增 5 项验收/回归覆盖改名引用与撤销、删除保护、数量合并与堆叠提示、产物顺序和输出槽校验、物品与配方新增后真实保存重开、资产绑定、窗口及搜索弹窗的筛选与选择。原 CSV 用例补充可选列及增删行保留检查。日志与结果：本地 `Logs/content-manager-stage2-final.log`、`Logs/content-manager-stage2-final.xml`。

## 阶段三：建筑页签与 factory.json 导入

### 建筑展示与编辑

- [x] 列表只显示图标、只读 Key 和名称，不显示占格缩略图。
- [x] 详情展示只读二维占格与端口图：坐标位于每格左上角，箭头放大；不提供占格、尺寸或端口编辑，修改依靠 Blender 导出或 CSV。单格传送带、垂直传送带、地基及坡道地基不展示占格区域。
- [x] 沿用 Blender 的占格坐标、端口边界和方向规则，复用 `FactoryBuildingFootprintUtility` 校验。
- [x] 名称保存到 `building_names.csv`，默认编辑 `zh-CN`，保留其他语言；图标绑定保存到表现表，复用已有图标烘焙入口。
- [x] 详情中配置 JSON 未提供的行为、加工类型、仓储容量、传送带 Tier/速度及坡度等；只显示对应行为需要的字段。
- [x] 删除建筑时删除其相关 CSV 行；默认保留 FBX、材质、纹理和 Prefab，避免误删共享资产。

### JSON 导入

- [x] 在建筑页提供“导入 .factory.json”文件选择入口；第一版支持单文件，预览与导入选项使用独立窗口。
- [x] 用明确的 DTO 读取当前 `schema_version = 1`，保留“字段缺失”和“数组为空”的区别，不在运行时增加 JSON 依赖。
- [x] 按 `building.key` 新增草稿或更新已有建筑，展示占格、端口、碰撞代理三个导入选项及简要预览。
- [x] 未包含的部分不更新；存在的空数组表示清空该部分；更新已有建筑时保留名称、图标和游戏属性。
- [x] 对 Unity 中已编辑过的空间数据，不自动覆盖；由用户在本次导入勾选需要覆盖的部分。不比较哈希，不做复杂三方合并。
- [x] 新增建筑缺少必需占格、行为或 Prefab 时保留为未保存草稿，补齐后再提交，不向 CSV 写入无效条目。
- [x] Processor 输出口沿用 JSON 的产物槽绑定，非 Processor 清除不适用的 `number/output_slot`。
- [x] 碰撞代理写入建筑导入配置，供下一阶段生成；JSON 中已转换为 Unity 局部坐标，不再次交换轴。

此阶段可以选择已有 `.prefab` 完成建筑保存，不依赖 FBX 自动生成先完成。

验收：完整 JSON 新增建筑；独立窗口预览并选择更新部分，取消不修改草稿；名称和已有空间数据在未勾选覆盖时保留；建筑列表无缩略图，详情空间图只读，指定单格节点隐藏。

实施记录（2026-11-02）：建筑页提供图标、只读 Key、名称和空间缩略图；详情使用二维占格/端口编辑器，按行为显示游戏属性，名称只更新 zh-CN，删除保留资产。单文件 v1 JSON 通过显式 DTO 解析，按 Key 更新草稿；占格、端口、碰撞代理分别预览和勾选，已有建筑默认不覆盖，缺失与空数组严格区分。Processor 保留产物槽绑定，非 Processor 清除不适用绑定。碰撞代理按现有 Unity 局部坐标保存至 `Assets/Settings/BuildingImports`，与 CSV 保存和数据库生成共同回滚；已有配置保留 GUID。缺少行为、Prefab 或有效占格的新建筑由候选校验阻止提交。操作见[内容管理器指南](../Guide/Factory-Content-Manager.md)。

验证：Unity 6000.3.19f1 完整 `Factory.Tests` EditMode 测试通过（324/324），新增建筑专项 5 项覆盖部分导入、空数组清空、撤销、占格与端口规则、槽位绑定、完整新增保存重开、配置写入失败回滚、资产保留和导入预览 UI。旧配方测试改用独立草稿/数据库副本构造多产物场景，适配当前示例 ABC → D；搜索弹窗测试使用指针事件，避免批处理窗口的键盘焦点影响验证。现有源 CSV 与生成数据库未改动。日志和结果：本地 `Logs/content-manager-stage3-final.log`、`Logs/content-manager-stage3-final.xml`。
界面调整（2026-11-03）：按使用反馈移除列表缩略图，将详情占格/端口改为只读；坐标放到每格左上角并放大方向箭头，单格传送带、垂直传送带及地基类隐藏空间区域。JSON 导入改用独立工具窗口，确认后将选中部分应用到原管理器草稿，取消不修改数据。上述规则取代初版的网格交互编辑流程。完整 `Factory.Tests` EditMode 回归通过（324/324）；UI 用例覆盖独立窗口取消/应用、默认勾选、列表无缩略图、只读详情及各类单格节点的隐藏规则。结果位于本地 `Logs/content-manager-building-ui.log`、`Logs/content-manager-building-ui.xml`。

## 阶段四：FBX 导入与材质适配

### 模型与 Prefab

- [x] 建筑详情增加 FBX 选择与“生成/更新 Prefab”入口；先尝试按 JSON 的 `model_file` 寻找配对文件，找不到时手动选择。
- [x] 外部模型复制到建筑对应的项目目录，纹理一并导入；已在项目内的 FBX 直接引用，不额外复制。
- [x] 使用 `ModelImporter` 的固定设置约定单位、轴向、动画和材质导入行为，避免每个建筑各自调整。
- [x] 使用一个非对称样例确认 FBX 与 JSON 的尺寸、朝向和底面中心原点一致，再固定导出/导入预设；不靠模型包围盒自动猜测原点。
- [x] 创建普通包装 Prefab：根节点保持单位变换，子节点承载 FBX 模型与生成碰撞体；建筑表引用包装 Prefab。
- [x] 更新时保留既有资产路径和 `.meta`，只更新工具负责的模型/碰撞子节点，不删除重建整套资产。

建议模型位于 `Assets/Art/Buildings/<key>/`，包装 Prefab 位于 `Assets/Prefabs/Buildings/`，沿用项目现有目录风格。

### 材质

- [x] 列出 FBX 源材质，优先在约定材质目录按名称匹配；重名时手动选择，不全项目模糊匹配。
- [x] 允许用户选择已有 `.mat`，利用 Unity 模型导入器的材质重映射保存引用。
- [x] 未匹配时可创建 URP/Lit 材质，简单承接颜色及可识别的贴图；复杂 Blender 节点不自动翻译。
- [x] 材质适配界面支持指定基础色、法线、金属度/光滑度、发光与透明设置。粗糙度转光滑度或通道不兼容时明确提示；首版不实现通用纹理打包器。
- [x] 源材质映射按“FBX 资产 + 源材质名称”维护，不只依赖槽位序号；源材质改名或新增时提示重新匹配。
- [x] 再导入模型时保留现有 `.mat` 和人工调整，不重复提取、创建或覆盖共享材质。

美术交付约定：模型、UV、稳定的材质分区名称；需要独特外观时交付图片贴图。最终 Shader 和渲染效果在 Unity 配置。

### 碰撞代理接入

- [x] 从建筑导入配置生成 Box、Sphere、Capsule 及 Cylinder 对应的碰撞数据，位置、旋转、尺寸按 JSON 使用。
- [x] Unity 普通 Collider 没有圆柱体：需明确使用项目 DOTS Physics 的圆柱形状或简单凸网格，不能替换成胶囊而悄悄改变外形。
- [x] 调整当前仅允许表现组件的 Prefab 校验，为工具生成的碰撞节点提供明确支持。
- [x] 接入现有建筑实体生成和拆除流程，确保碰撞跟随建筑放置旋转、楼层及生命周期；仅让 Prefab 显示代理不算完成碰撞。
- [x] 复用现有 Physics/烘焙机制；只添加必要的建筑碰撞配置，避免新建通用碰撞框架。

验收：一个建筑完成 FBX + JSON 导入、材质匹配、Prefab 生成；替换 FBX 后材质仍正确；游戏内放置、旋转和拆除时碰撞正确。

实施记录（2026-11-03）：建筑详情支持 JSON 同目录配对 FBX、项目内选择与外部模型/纹理导入，固定 ModelImporter 的单位、轴向、动画及材质设置。包装 Prefab 保持单位根变换，以 `Factory Model` / `Factory Collisions` 两个工具子节点承载模型与碰撞；更新保留资产路径、GUID 和其他人工子节点。源材质在约定目录按名称匹配，重名手动选择；支持已有 .mat 重映射、URP/Lit 创建及原生 Inspector 调整，提示粗糙度/光滑度通道要求，重复导入保留人工材质。资产操作立即落盘，CSV 与导入配置引用继续使用原草稿保存流程。

碰撞代理参数移至 Runtime，包装通过现有 Baker/BlobAssetStore 烘焙共享 compound collider。Box、Sphere、Capsule 和 Y 轴 Cylinder（Unity Physics 原生 32 边圆柱）保留 JSON 局部姿态。建造命令将碰撞挂到逻辑根实体，随四向旋转、楼层和拆除生效；人物过滤器接入建筑类别，地基拾取不受建筑碰撞干扰。地基分块、坡道等专用地形继续沿用原物理机制。人工 Prefab 不会被工具覆盖，需清空引用后生成独立包装。

验证：使用本机 Blender 4.1.1 和插件导出 testMachine（2 个模型网格、5 个端口、2 个碰撞代理），固定 FBX 预设确认偏心柱体 Unity 中心 `(0.6, 1.939839, 0.75)`、高度 2 和底座 Y=0；导出脚本与交付样例保存在 `Tools/Blender`。Unity 6000.3.19f1 完整 `Factory.Tests` EditMode 通过（331/331），新增 7 项覆盖坐标/单位/原点、材质创建及复用、稳定 GUID 与人工子节点、真实 Baker、完整 JSON+FBX 保存重开、四种形状及四向旋转/楼层/拆除。新增 Ecs 场景 PlayMode 验收通过（1/1）：上层旋转放置后 PhysicsWorld 射线命中 testMachine 代理，拆除后碰撞消失。测试恢复源 CSV 与数据库，不更改原 testMachine.blend。日志与 XML：本地 `Logs/content-manager-stage4-verified.*`、`Logs/content-manager-stage4-physics-verified.*`。流程见[内容管理器指南](../Guide/Factory-Content-Manager.md)。

## 必要检查与验收边界

只保留必需检查：文件可读取、协议版本、重复 Key/ID、必填引用、正数数量/耗时/尺寸，以及现有占格/端口/产物槽规则。错误在当前条目显示，并复用现有数据库校验，不复制整套规则或引入 JSON Schema 校验引擎。

验证以以上各阶段的少量操作验收为主。必要时仅为容易误读的 JSON 部分导入和 CSV 转义补少量自动化用例；不做全组合测试、哈希比对、压力测试或独立测试基础设施。

本期不包含：运行时热更新、存档迁移、完整多语言系统、资源自动监控同步、批量材质节点转换、通用资产依赖管理。现有数字 ID 机制保持不变，Key 用于源数据关联。
