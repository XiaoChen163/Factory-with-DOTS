# 未来计划 2：最小玩法循环与首个可玩 Demo

更新日期：2026-11-04  
状态：规划，以下任务尚未作为已实现功能验收。

## 1. 目标与范围

本计划承接 [未来计划](Future-Plan.md)，以 [玩法构想对话](FactoryFPS-ChatLog.md) 为设计背景，遵循 [玩法开发框架](../Guide/Gameplay-Development-Framework.md)。任务编号表示建议实施顺序，不代表工期承诺。

首个 Demo 按单机、小型手工地图设计，依次完成两个循环后交付：

1. **工业战斗循环：生产物资 → 进攻据点 → 获得资源或配方 → 扩展生产。**
2. **安防夺回循环：配置安防 → 应对渗透 → 局部失守 → 潜入夺回 → 恢复生产。**

第一步完成后只进行内部玩法验证；第二步完成并通过交付验收，才形成首个对外可玩的 Demo。第二步包含必要的引导、反馈、构建和稳定性工作，不另等完整游戏系统齐备。

### 已有基础

- 工厂生产与物流原型。
- 网格建造、地基、坡道、多层空间、建筑碰撞与放置预览。
- 第一人称角色；移动碰撞由 ECS 驱动，输入、相机与动画由 GameObject 接入。
- 库存、UI、玩家命令入口与 UI 快照出口。
- Blender 建筑制作插件与 Factory 内容管理器。

沿用以上能力；实施新功能时检查兼容性，不重复建立第二套库存、建造或角色控制框架。

### Demo 内容上限

| 项目 | 初始范围 |
|---|---|
| 地图 | 一张非方块灰盒地形地图，玩家基地、一个可争夺前哨、一个安全重生区；工厂建设在地基上 |
| 工业 | 少量基础资源；弹药、修补件及必要建材的短生产链；机器人可用简化配方部署 |
| 枪械 | 一把基础枪、一种弹药，射线命中，不做完整改装 |
| 机器人 | 一种共用基础机体，区分守卫、驻守敌人、渗透任务；以个位数至十余台规模验证 |
| 安防 | 一种有视野遮挡的近程侦测器；驻守与警报响应 |
| 电力 | 一种发电设施、简单供电连接与供需规则 |
| 基地 | 控制中枢、一个信标；验证局部失守与夺回 |
| 流程 | 目标约 30～45 分钟，可从头重开；实际时长通过试玩调整 |
| 持久化 | Demo 不要求跨会话存档；提前设计稳定 ID 和可保存状态 |

不纳入首个 Demo：大地图流式加载、完整科技树、大规模敌袭、远程雷达、防空与空战、复杂武器配件、完整敌方工业经济、自动扩建 AI、多人联机。正式玩法关闭原型自由飞行和无限建造资源，调试入口只在开发模式保留。

## 2. 排布原则与工程边界

1. 先消除动态导航、战斗结算和归属转换风险，再增加内容数量。
2. 每项任务都交付可独立验证的行为；前置未通过时，不用美术或数值扩充掩盖问题。
3. ECS 保存正式玩法状态：库存、武器、伤害、机器人、归属、供电、占领与重生资格。MonoBehaviour 负责输入、相机、视模、动画、音效、UI 和创作接入。
4. 低频操作沿用命令入口；移动、瞄准、扳机使用可复用的持续输入通路。表现读取快照并消费一次性事件，不重复结算玩法。
5. 正式身份使用稳定 ID；Entity 引用只是运行时关联。基地成员关系显式记录，不能由地基连通自动推导归属。
6. 固定 Tick 推进正式模拟；感知与决策可以按 Tick 分批执行。明确物理查询、伤害、死亡、占领、重生的结算顺序。
7. 新系统按世界空间、工业后勤、战斗、单位安防、基地归属、战役事件、表现与持久化分领域组织，暂不要求拆分程序集。
8. 定义数据接入现有数据库和内容工具；只增加当前任务必需字段，不先开发通用 AI 编辑器或大型任务编辑器。

## 3. 第一步：工业战斗最小循环

### 3.1 任务顺序

| 顺序 / 编号 | 任务与交付物 | 前置 | 验收标准 |
|---|---|---|---|
| 1 / A01 | **规则与数据契约**：统一阵营、伤害目标、武器与弹药定义；确定稳定对象 ID、基地 ID、命令与事件边界 | 已有框架 | 玩家与机器人能够引用同一套战斗定义；明确死亡、库存扣除和物品转移的唯一结算方 |
| 2 / A02 | **灰盒战场与导航风险试验**：非方块地形、地基与坡道碰撞；路径请求接口、建筑变化失效机制；选定 Demo 导航方案 | A01 | 机器人能在地形和地基间通行；放置建筑堵路后改道，拆除后恢复；无法到达时明确失败，不无限撞墙 |
| 3 / A03 | **生命值、阵营与伤害结算**：玩家和机器人受伤、死亡、清理；固定安全点重生 | A01、A02 | 敌我规则一致；死亡只处理一次；重生不会残留旧角色碰撞或重复控制；原型自由飞行不进入正式流程 |
| 4 / A04 | **第一人称基础枪械**：瞄准、射速、弹匣、备弹、换弹、命中、基础反馈；射击与建造/UI 输入仲裁 | A03 | 扣弹与命中由 ECS 结算；空弹匣不能射击；按住自动射击不依赖渲染帧率；操作 UI 不误开枪；建筑遮挡有效 |
| 5 / A05 | **驻守敌人**：巡逻或驻守、视野发现、追击、攻击、丢失目标后搜索/返回；使用同一武器与伤害规则 | A02～A04 | 玩家能利用遮挡接近、脱离与交战；敌人不隔墙射击、不持续掌握不可见目标位置；多个单位相遇可恢复通行 |
| 6 / A06 | **资源点与正式建造成本**：矿点类型、开采资格和产出绑定；有限起始物资；接入现有库存与建造命令 | A01、A02 | 无矿点的矿机不能凭空产矿；库存不足不能建造；放置失败不扣物资；拆除返还规则固定，不可复制物资 |
| 7 / A07 | **战斗生产链**：弹药和修补件定义、配方、加工、运输、入库、取用；基础武器可由起始物资提供 | A04、A06 | 玩家能用开采产物制造并取用弹药，射击确实消耗这些物资；修补件可制造和入库，其维修用途在 B01 接入 |
| 8 / A08 | **进攻收益与流程引导**：前哨目标、清除驻军后的交互奖励；解锁一个影响生产的配方或资源点 | A05、A07 | 玩家完成进攻后获得可持续收益，回基地能够实际扩展生产；奖励不重复领取，关键道具不随机缺失 |
| 9 / A09 | **第一步整体验收与调参**：从新游戏跑通生产、补给、进攻、收益、扩产；校准弹药与敌人数量 | A08 | 不用调试指令可完成一轮；玩家有生产弹药的实际理由；失败后能够重新进入循环，不因初始资源耗尽永久卡死 |

修补件在第一步形成生产能力，在第二步开始承担战斗消耗。A08 的前哨奖励是最小目标交互，不代表此时已实现完整基地占领。

### 3.2 阶段出口

第一步完成时，应能回答：

- 战斗是否让玩家主动调整生产或准备补给？
- 战斗奖励是否带来可见的生产变化？
- 角色、敌人和建筑碰撞是否共享一致的战斗空间？
- 玩家是否能够理解缺弹、生产不足、无法到达等失败原因？

若循环只靠场景赠送弹药维持，或敌人主要依赖卡路才能被击败，应在此阶段修正，再进入第二步。此里程碑不作为首个 Demo 的交付点。

## 4. 第二步：安防、失守与夺回循环

### 4.1 任务顺序

| 顺序 / 编号 | 任务与交付物 | 前置 | 验收标准 |
|---|---|---|---|
| 10 / B01 | **建筑瘫痪与维修**：受损、瘫痪、修复、重启；统一修补件消耗；生产/运输适用范围明确 | A09 | 瘫痪保留建筑、布局及库存；相关功能停止；修复不复制或吞掉在制品、端口物资；短暂重启过程可被攻击打断 |
| 11 / B02 | **基地成员与权限**：基地、中枢、设备归属；访问库存、建造、拆除、维修和操作权限 | B01 | 敌方库存不能绕过规则取用，敌方建筑不能被免费拆除；相邻地基不意外合并基地；移动机器人保留独立阵营 |
| 12 / B03 | **最小电力与设备可用状态**：简单连通供电；供需不足与断电规则；统一工作状态判断 | B01、B02 | 发电设施停机后相关设备停机；修复后恢复；UI 能区分无电、瘫痪、缺料；启动能源不依赖尚未启动的同一条生产链 |
| 13 / B04 | **侦测与警报**：近程视野、遮挡、最后发现位置、警戒状态、警报来源与清除规则 | B03、A05 | 遮挡与朝向影响发现；设备断电或瘫痪后停止发现新目标；已发出的警报按规则衰减，不凭空传递敌人实时位置 |
| 14 / B05 | **友方机器人部署与指挥**：消耗简化工业品部署；移动、驻守、警报响应、人工补给 | B04、A07 | 玩家能配置小队并使其赶到警报位置交战；机器人消耗实际弹药；缺弹可见且能补给；单位数量有 Demo 上限 |
| 15 / B06 | **可控渗透事件**：小队从合理入口进入，选择有限目标，如侦测器或发电设施；有结束条件和冷却 | B05 | 敌人不在基地内部凭空生成；渗透可被发现、阻止，也可造成可修复损失；无持续刷兵导致的无限维修压力 |
| 16 / B07 | **中枢接管与信标**：信标决定本地复活资格；中枢通过有时长、可中断的交互转换基地归属 | B02、B06 | 信标失效不等于瞬间失守；敌人必须完成接管；接管后权限、侦测敌我判断和生产访问一致更新，旧交互请求重新校验 |
| 17 / B08 | **远处重生与固定补给包**：死亡时无可用信标进入安全区；最低生存与夺回物资；保留已解锁进度 | B07 | 有信标时本地复活，无信标时安全复活；补给按失败阶段和可恢复库存补足，不能靠连续自杀重复囤积；失败仍可再次尝试 |
| 18 / B09 | **简化敌方接管运营与潜入夺回**：有限驻军、预算内分阶段修复、巡逻；可切电、绕视野、交互黑入中枢 | B04、B07、B08 | 玩家能够利用自己布置的路线和遮挡夺回基地；黑入受距离、时长与打断规则约束；敌人恢复有上限；夺回后可维修并恢复生产 |
| 19 / B10 | **Demo 场景与新手流程整合**：目标提示、操作提示、警报位置、部队状态、占领进度、失败恢复说明 | B09 | 新玩家不依赖开发者口头说明完成两个循环；资源、路径、守军和交互位置支持至少一种稳定可行的完成路线 |
| 20 / B11 | **Demo 交付验收**：构建、完整试玩、回归、基准性能与问题修复 | B10 | 满足下述交付清单；独立构建中能开始、完成、失败重试和重开流程 |

### 4.2 Demo 规则收敛

- **局部失守承载特色体验。** 主要争夺对象是小前哨，主基地提供继续游玩的保障；无可用信标的恢复流程另有明确可触发场景。
- **夺回体验不以强迫惨败为前提。** 提供“继续防守”与明确标识的“夺回演练”入口。演练复用玩家当前前哨布局，在说明后布置受控失守状态；不伪装成玩家无法阻止的普通战斗。
- **电力使用最小明确规则。** 可以采用显式节点连接和简单供需判定；欠供策略必须统一并可见。暂不加入电压、复杂负载优先级与大型储能调度。
- **建筑瘫痪不直接删除布局和库存。** 传送带是否可受损需统一；Demo 可限制为关键生产、能源、安防和控制设备，避免过早增加运输恢复复杂度。
- **接管不能凭空翻转机器人阵营。** 敌方驻军是有上限的部署；存活友军继续按自身阵营行动。设备权限由基地归属与局部黑入状态共同判断。
- **停机原因分开保存。** 断电、瘫痪、缺料和权限不足不能共用一个会互相覆盖的布尔值。
- **基础补给保持可恢复。** 固定包先保证一次合理夺回尝试；反刷限制不能使再次失败的玩家永久失去行动能力。每次发放、残留包和死亡掉落使用明确记录，防止叠加套利。
- **安防有合法绕行机会。** 场景保留可观察、可利用的路径；不能把“敌人故意看不见”作为唯一潜入机制。完整听觉、复杂掩体战术可后置。

### 4.3 首个可玩 Demo 交付清单

- [ ] 一张完整灰盒地图，具备两步循环所需场景、资源和路线。
- [ ] 第一轮生产、补给、主动进攻、奖励与扩产自然连通。
- [ ] 侦测器与机动守卫能实际影响渗透结果。
- [ ] 可体验一次局部失守、重生/撤离、潜入夺回与恢复生产。
- [ ] 基础枪械命中、后坐反馈、声音、受伤反馈足以判断战斗结果。
- [ ] 生产、断电、瘫痪、缺弹、警报和接管状态清楚可见。
- [ ] 无编辑器依赖地开始游戏、暂停、重试、重开和退出；说明当前 Demo 无跨会话存档。
- [ ] 正式入口关闭无限物资、自由飞行和测试用直接胜利操作。
- [ ] 验证新游戏重开不会残留旧世界命令、库存、机器人或警报。
- [ ] 按框架运行相关系统回归及完整 `Factory.Tests`；涉及 UI/交互时运行 `Factory.PlayModeTests`。
- [ ] 单独验证瘫痪恢复物资守恒、重复伤害/死亡、接管权限切换、旧命令拒绝、无信标重生和重复补给防刷。
- [ ] 在声明的测试机器、分辨率和 Demo 最大内容量下记录帧时间、模拟时间与 GC；以 60 FPS 为初始目标，验证机器人交战和工厂运行同时发生时无持续明显卡顿。
- [ ] 至少完成一轮无人讲解试玩和一次独立构建完整通关，修复阻断流程与资源死锁问题。

性能验收使用 Demo 目标规模与现有采样方式，不自动扩展成大规模压力测试；超出范围的压力测试另立任务。交付物包括可运行构建、操作说明、已知问题和验收记录。完成 B11 后，首个可玩 Demo 里程碑关闭。

## 5. Demo 完成后的建议完善顺序

先依据试玩结果修正核心循环，再扩大世界与内容。以下为默认顺序；如果 Demo 暴露导航、射击或恢复循环问题，优先回到对应模块修复。

| 顺序 / 编号 | 后续工作 | 排在这里的原因与完成标志 |
|---|---|---|
| 1 / C01 | **试玩反馈与基础体验修整**：枪械手感、导航可靠性、建造/射击切换、警报理解、经济节奏 | 先确认核心体验值得扩展；玩家能理解失败原因，守卫和夺回不依赖偶然行为 |
| 2 / C02 | **正式存档与读档**：一致快照、稳定 ID 映射、版本号、备份；保存库存、在制品、基地归属、资源与战役进度 | 支持超过一次短局的游玩；加载后重建导航、电网等缓存，物资和权限保持一致；暂停/退出语义明确 |
| 3 / C03 | **自动后勤与维护**：机器人自动补弹/充电、维修任务、库存阈值与任务优先级 | 扩大工厂前先消除重复跑腿；玩家离开后基地能维持常规运行 |
| 4 / C04 | **正式敌袭调度与地区威胁**：冷却、准备期、可解释的威胁来源、渗透与正面攻击区别、失败恢复窗口 | 取代 Demo 的固定事件；玩家能建设与探索，敌袭不会持续打断所有活动 |
| 5 / C05 | **区域安防与中等规模进攻**：分区响应、巡逻、听觉/搜索、集结点、队伍指挥；雷达分级预警 | 在可靠后勤和明确袭击规则上扩大防卫决策；验证规模前先定义单位数量和帧时间预算 |
| 6 / C06 | **科技与工业纵深**：新资源、新配方、蓝图奖励、机器人能力成长、武器选择 | 保持旧资源与基础装备价值；升级带来新选择，关键技术无资源依赖死锁；视实际配方需求加入化工/流体 |
| 7 / C07 | **多基地与较大地图**：更多资源区、前哨、远程物流、跨基地权限；区块加载与远处模拟 | 先定义离屏生产、远处战斗与占领规则，再做流式；卸载区域不应清除威胁或改变归属结果 |
| 8 / C08 | **大规模进攻与调度优化**：批量感知、导航预算、远近单位更新频率、分层指挥 | 在明确的地图和目标规模下做针对性优化；以性能证据决定是否替换导航或动画方案 |
| 9 / C09 | **空中威胁、远程雷达与防空阵地**：空中路径、探测、导弹/拦截、弹药与供电 | 地面安防成立后再新增完整威胁维度；防空负责空中目标，不替代地面反渗透 |
| 10 / C10 | **完整战役与内容打磨**：终局目标、敌方设施变体、地图美术、音频、引导、可访问性与长期平衡 | 将已验证的系统组织成完整游戏流程；明确胜利条件、成长曲线和不同战术的收益 |

以下事项保持为可选扩展，不自动进入以上主线：完整敌方生产与扩建 AI、复杂武器改装、程序化大世界、多人模式。只有玩法验证或明确产品目标需要时再单独立项。

## 6. 建议的系统架构划分

本节是实施起点，**可能需要结合实际代码、导航方案、试玩结果和性能测量修改**。表中的新组件、系统组和接口名称均为建议，不表示已经存在，也不要求一次性建立全部框架。优先保持状态归属和模块职责清楚；具体类数量、目录拆分和调度粒度可随任务演进。

### 6.1 总体结构与状态归属

```text
内容定义 / 场景创作
    └─ 现有导入器、校验与 Baking → ECS 定义数据和初始实体

输入 / UI / 调试入口
    └─ 命令或持续控制意图 → 接入与校验 → ECS 领域系统
                                              ├─ 只读快照 → UI / 动画 / 相机
                                              ├─ 一次性事件 → 音效 / 特效 / 通知
                                              └─ 一致存档快照 → C# 序列化与磁盘服务

导航等外部服务
    └─ 带版本的请求 / 结果 ↔ ECS 适配层
```

- **定义数据**：物品、配方、武器、机器人和设备规格，沿用现有数据库与内容工具；运行时只读，不能让编辑器源表与生成 Asset 成为两份独立真源。
- **权威运行状态**：位置、生命、库存、供电、任务、归属、科技进度等由 ECS 保存。一个状态只有一个负责提交变更的模块。
- **派生缓存**：占用索引、导航数据、电网连通、可用信标列表和 UI 快照可以重建，不应反过来成为正式身份或归属的依据。
- **表现状态**：镜头平滑、武器摆动、动画混合、音效播放和窗口开关留在表现层；不决定扣血、扣弹、占领或物资转移结果。

当前代码已有 `PlayerCommandBus`、`PlayerCommandIngressSystem`、`PlayerCommandResultExportSystem`、`UiSnapshotExportSystem` 和 `UiDataHub`，优先扩展这些边界。`EcsCharacterMotor` 已承担角色生命周期、控制输入和表现同步；可以保留其适配职责，不必为了统一形式重写，但不能继续向其中堆放武器、库存或基地规则。

### 6.2 领域模块与责任边界

| 模块 | 负责的状态与行为 | 对外提供的能力 | 首次落点 |
|---|---|---|---|
| 世界与建造 `World / Construction` | 网格、表面、建筑占用、地形碰撞、资源点；建造与拆除 | 空间查询、建造结果、区域变更版本；不判断机器人战术 | A02、A06；复用已有系统 |
| 工业与库存 `Industry / Inventory` | 生产、端口、运输、容器、物资扣除与转移 | 原子取用/转移请求、库存与生产状态；战斗不得另建弹药资源账本 | A06、A07 |
| 能源与设备 `Power / Devices` | 电网、供需、设备工作条件 | 供电结果、设备不可用原因；不直接接管战斗或基地归属 | B01、B03 |
| 战斗与生存 `Combat` | 武器状态、射速、弹匣、命中、伤害、生命、死亡、建筑损伤与维修结算 | 开火/伤害/维修请求，开火/命中/死亡事件 | A03、A04、B01 |
| 导航与移动 `Navigation / Movement` | 路径请求、路径跟随、通行失败与重规划、实际移动 | 可达路径、移动状态；只执行目标，不决定攻击谁 | A02、A05 |
| 感知与安防 `Perception / Security` | 视野、遮挡、最后发现位置、警戒、侦测器、警报 | 带来源、位置、时间和有效期的观测与警报；不提供无条件全图透视 | A05、B04 |
| 单位决策与指挥 `Units / Orders` | 个体状态机、小队命令、驻守点、警报响应、补给任务 | 移动意图、瞄准/开火意图、补给请求；不自行扣伤害或传送单位 | A05、B05；自动后勤 C03 |
| 基地与权限 `Bases / Ownership` | 基地成员、阵营关系、设备操作权限、中枢接管、局部黑入 | 有效权限、归属变更、可用重生地点查询；机器人阵营独立 | B02、B07 |
| 战役与恢复 `Campaign / Recovery` | 阶段目标、奖励、科技、敌袭调度、占领后运营、死亡后的重生选择和补给发放记录 | 生成/部署/复活请求；通过其他模块完成物资、位置和归属变更 | A08、B06、B08、B09 |
| 表现与交互 `Presentation` | 输入仲裁、相机、视模、UI、动画、声音、特效 | 玩家意图与只读状态呈现；不维护第二份玩法状态 | 随每项任务接入 |
| 持久化 `Persistence` | 一致快照、格式版本、编码、读写、稳定 ID 重映射 | 保存/加载结果；加载后要求各模块重建派生缓存 | A01 约定身份；C02 正式实现 |

模块之间优先通过明确请求与只读状态协作，不建立所有系统都能任意改写数据的全局管理器。也不必把每次内部调用都变成事件：同一领域内有顺序保证的组件读写，可以保持直接和简单。

### 6.3 建议的对象与公共能力

| 对象 | 建议组合的能力 | 注意事项 |
|---|---|---|
| 玩家 / 机器人 | 稳定身份、阵营、生命、移动、武器、库存或装备槽 | 共用战斗规则，输入来源分别是玩家与 AI；表现可不同 |
| 工业设备 | 建筑身份、基地成员、损伤状态、生产/运输能力、供电需求 | 瘫痪保留库存；是否需要电力按设备定义，不默认所有建筑相同 |
| 侦测器 / 雷达 | 建筑公共能力、探测配置、观测/警报输出 | 近程侦测和远程预警分别扩展；停电通过设备工作条件影响探测 |
| 防空阵地 | 建筑公共能力、目标筛选、武器、弹药库存 | 后期组合已有探测与战斗能力，避免再造伤害和库存系统 |
| 控制中枢 | 基地关联、接管进度、交互权限 | 接管完成后集中提交归属变更；不能由 UI 直接改阵营 |
| 重生信标 | 基地关联、工作状态、重生资格 | 信标不是基地归属的唯一来源；复活前重新检查资格 |

建议至少区分 `FactionId`、`BaseId`、稳定对象 ID 与运行时 Entity 引用。基地级归属可由成员引用查询，局部黑入作为显式覆盖状态；如为性能缓存有效阵营，应带归属版本并在权限使用前确保一致。不要要求接管时逐设备同步一份永远不会过期的所有者副本。

枪械弹匣中的子弹与背包备弹可以分别表示，但换弹必须是库存扣除与弹匣增加的一次受控事务；死亡掉落、补给、存档均沿用同一物资规则。维修也要先校验条件，再在同一结算边界扣修补件并提交修复。

### 6.4 ECS 与 MonoBehaviour 的具体分工

| ECS / 模拟层 | MonoBehaviour / 表现及服务接入层 |
|---|---|
| 校验开火、扣弹、推进换弹、物理命中与伤害结算 | 采集瞄准和扳机输入、视模、镜头反馈、播放开火音效 |
| 机器人感知结果、状态机、任务和实际移动 | Animator 参数、可见模型、选中标记；必要时接入导航服务 |
| 建筑、电力、归属、信标、重生和战役状态 | 状态提示、交互进度条、镜头切换和场景表现 |
| 一致的存档数据提取与加载后的状态恢复 | 普通 C# 服务执行序列化、磁盘读写；不要求这些服务继承 MonoBehaviour |

大量重复计算再按测量结果使用 Burst/Jobs；少量基地规则可以先用清楚的 ECS 系统实现。Demo 不要求每个机器人对应的表现对象都改成纯 ECS 渲染，也不允许表现对象消失就让机器人从模拟中消失。

### 6.5 桥接协议与更新顺序

**输入分两路：**

- 持续状态：移动、瞄准、按住扳机，用可复用缓冲提交；固定 Tick 读取最新合法状态。
- 一次请求：换弹、建造、维修、黑入、驻守命令，携带请求序号与目标身份，返回成功或失败原因。半自动开火等短按边沿需缓存，不能在两个 Tick 之间丢失。

低频命令可沿用现有入口；高频战斗通路避免每帧创建托管集合。接入层只负责传递和基础校验，领域系统在实际执行时再次校验生命、权限、库存和目标有效性，防止接管或死亡后执行过期命令。

**输出分两路：**

- 状态快照：生命、弹药、设备状态、任务、警戒、占领进度。按观察范围和 Revision 更新，UI 不逐帧遍历全世界。
- 一次性事件：开火、命中、死亡、警报提示、占领完成。使用事件序号/Tick 与消费边界，既不跨渲染帧重复播放，也不在一帧发生多个模拟 Tick 时丢掉中间事件；不无限保存历史事件。

建议按以下逻辑阶段安排更新，具体系统组和前后关系必须在实施时对照现有代码确定：

| 阶段 | 建议职责 |
|---|---|
| 接入阶段 | 收集输入和请求；确认其提交到哪个模拟 Tick |
| 固定 Tick 的决策与控制阶段 | 消费已有观测、推进单位任务、生成移动/瞄准/开火意图；低频决策按 Tick 分批 |
| 物理与战斗阶段 | 在约定的物理世界时刻执行移动和命中；统一提交伤害与死亡 |
| 设备与工业阶段 | 更新损伤、供电和可用性，按已确定顺序推进生产与运输 |
| 基地与流程阶段 | 结算接管、复活资格、奖励和事件调度；避免已死亡单位继续完成交互 |
| 表现阶段 | 导出结果、快照与事件，插值位置并更新表现 |

以上是逻辑依赖，不是可以直接照搬的一条系统执行列表。现有角色在 `KinematicCharacterPhysicsUpdateGroup` 内运行，工厂已有固定更新顺序；新增系统不能任意移动这些系统。A02/A04 实施时要确定命中查询使用哪一个物理快照，并验收移动目标、墙边射击和新建障碍；B03/B07 要明确停机与接管在本 Tick 还是下一 Tick 对生产生效。允许有定义的一 Tick 延迟，不能依赖碰巧的系统注册顺序。

### 6.6 导航、物理与空间的适配边界

- 地形、地基和建筑须向实际移动与战斗查询提供一致的碰撞信息。沿用现有 ECS 物理体系，不能默认 GameObject 射线会命中 ECS 碰撞体。
- 导航请求至少包含单位身份、请求序号、起终点和通行能力；返回路径或失败原因，并携带请求/导航版本。过期结果不能覆盖新任务。
- 建造与拆除通过局部脏区域或 Revision 通知导航更新；保留现有表面、建筑占用和运输拓扑的职责区分，不因任何变化全图重建所有索引。
- 如选择 GameObject 导航适配器，只让它提供路径或导航结果，由 ECS 移动系统推进实际位置；不同时让两个控制器写位置。
- Demo 先解决可达性、改道和拥堵恢复，再增加掩体、复杂躲避、编队与大规模流场。导航方案最终由 A02 试验决定。

### 6.7 目录与分阶段落地建议

2026-11-04：现有源码已按技术层下的领域子目录整理，实际目录和查找入口见 [Scripts 源码目录导航](../Guide/Scripts-Directory-Map.md)。本次仅调整源码位置，保留类名、程序集、脚本 GUID 与运行行为；以下结构仍作为未来领域扩展参考。

沿用 `Factory.Runtime` 和现有目录，只在规模需要时增加领域子目录，例如：

```text
Assets/Scripts/
  DataBase/                     定义数据、导入与 Editor 工具
  ECS/
    Data/{Combat,Units,Bases,...}/
    Systems/{Combat,Units,Bases,...}/
    Authoring/                  Baker 与场景创作适配
    Presentation/               输入、相机、动画、UI 与表现桥接
    Performance/                已有性能采样与场景接入
  Persistence/                  后续存档编码与 I/O 服务
```

花括号表示可选领域子目录，不是要求创建的字面路径。现有文件不为目录美观批量迁移；新增代码遵循当前程序集与测试规则。没有真实第二个实现前，不先为所有系统建立通用服务接口。

| 实施阶段 | 必须建立的架构边界 | 暂缓事项 |
|---|---|---|
| A01～A05 | 身份、统一战斗状态、输入与事件协议、导航接口、权威位置 | 通用行为树编辑器、完整单位调度平台 |
| A06～A09 | 库存事务、建造成本、资源点、奖励与解锁边界 | 完整科技树、完整存档服务 |
| B01～B05 | 设备可用性、基地成员、权限、能源、警报和单位命令 | 复杂电网、跨基地调度 |
| B06～B11 | 接管事务、重生恢复、补给记录、世界重开清理、Demo 流程 | 大世界分区、完整敌方工业 |
| C02 及以后 | 存档版本与缓存重建；按实际需求扩展自动化与世界运行 | 无性能证据的全面重构 |

需要修改本建议时，在相关任务中记录“原假设、实际约束、采用方案、影响与验收方式”，同步更新本节。保持唯一权威状态、清楚的物资事务和可验证的时序；具体导航实现、组件布局和目录组织可以调整。
