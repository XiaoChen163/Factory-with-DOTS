# Demo 美术资产清单：Low Poly

更新日期：2026-11-04。状态：制作与验收清单，不表示资产或动画播放功能已经完成。

关联计划：[未来计划 2](Future-Plan-2.md)。交付目标为先后完成“工业战斗循环”和“安防夺回循环”的首个单机 Demo。

## 1. 美术方向与范围

**游戏美术风格确定为 Low Poly。** 以清楚的几何轮廓、简洁的色块与材质、易辨认的功能部件构成工业场景。第一人称近景资产要保持完整轮廓和合理关节，不以低面数为由牺牲握枪、机械运动和交互可读性。

- 统一角色、武器、建筑、环境的细节密度和配色；避免同场混用明显写实与低多边形资产。
- 优先使用共享材质、有限色板与少量纹理；是否使用平滑法线按造型决定，不要求所有表面都硬边。
- 友敌身份同时使用颜色与标志/形状提示，不能只依赖红绿差异。
- 资源、弹药、修补件和关键设备在实际游玩距离下应能通过轮廓辨认。
- 面数、纹理尺寸、材质数量与动画开销在首批样机导入后确定预算，后续同类资产遵守该预算；Low Poly 不等于可以无限增加材质、透明效果和动画对象。
- Demo 只做一张小地图、一种基础机器人、一把枪、短生产链及必要安防设备。暂不制作完整武器系列、雷达、防空、空中敌人、大型城市或完整科技树资产。

优先级：**P0** 为第一步循环必需，**P1** 为第二步循环必需，**P2** 为 Demo 交付前的统一与打磨。现有资产标注“复用检查”只说明项目已有文件，仍需检查 Low Poly 风格、比例、材质、动画和导入适配。

### 1.1 自然环境与人造建造物的边界

- **非方块部分仅限自然地形和植被。** 岩壁、岩石与矿点外观属于自然环境；Low Poly 是整体视觉风格，不改变建造规则。
- **人造场景物体依赖地基建设。** 玩家基地和敌方前哨遵守相同规则，不另设可直接任意摆在自然地面的人造场景物件体系。此处指固定建造物，不限制角色、机器人和可携带物品的移动。
- **工业墙体通过不同材质的地基表达。** 复用地基网格、堆叠和碰撞规则，美术提供墙面用途的地基材质变体，不另做自由摆放的工业墙体模块系统。
- **围栏等道具归为装饰型建筑。** 每种具有自己的占格、朝向、碰撞/遮挡定义，必须依附合法地基放置；箱堆、废弃设备、标识牌等固定人造布景也按此规则制作。
- 装饰型建筑不参与工厂设备加工，不配置加工配方、加工进度或物流端口，也不强制提供 Idle/Working 两态。它仍可按实际几何影响通行、视线和射击遮挡；“装饰”不代表无碰撞。

## 3. 工厂与安防设备

**每种加工机器必须提供空闲（Idle）和工作（Working）两种动画状态，空闲可以完全静止。** 同一模型通过多个配方承担生产时可共享动画，但不同机器必须各自配置并验收。两态的详细交付规则见第 4 节。

| ID | 资产 | 最小数量 | 制作与状态要求 | 优先级 |
|---|---|---|---|---|
| BL01 | 地基与坡道 | 1 套，复用检查 | 材质、边缘、接缝与尺度统一；包含用于工业墙体的地基材质变体，复用地基堆叠与碰撞规则 | P0 |
| BL02 | 传送带模块 | 1 个等级，复用检查 | 直线、转角、合流、分流；垂直运输完善 Demo 实际使用的模块；移动表现与现有物流逻辑对齐 | P0 |
| BL03 | 矿机 | 1 种，复用检查 | **Idle + Working**；空闲可静止，工作可用钻头旋转/往复；出料口明确 | P0 |
| BL04 | 熔炉 | 1 种，复用检查 | **Idle + Working**；工作可用机械运动配合炉光等循环表现，与空闲明显区分 | P0 |
| BL05 | 通用装配设备 | 1 种，可改造现有机器 | **Idle + Working**；承担弹药、修补件和简化部署材料生产，可使用压头、夹具、机械臂循环 | P0 |
| BL06 | 仓储设备 | 1 种，复用检查 | 存取位置明确；不是加工机器，不强制制作工作循环 | P0 |
| BL07 | 发电设施 | 1 种 | 运行、停机、瘫痪可区分；建议复用两态表现机制；供电接口明确 | P1 |
| BL08 | 近程侦测器 | 1 种 | 传感头朝向清晰，工作灯与警报反馈；扫描运动不得与实际探测方向冲突 | P1 |
| BL09 | 控制中枢 | 1 种 | 可交互面板、阵营标志与接管反馈；轮廓区别于信标 | P1 |
| BL10 | 重生信标 | 1 种 | 激活/不可用状态与作用范围提示清楚 | P1 |
| BL11 | 补给箱 | 1 种 | 安全重生补给容器，未领取/已领取可区分 | P1 |
| BL12 | 机器人部署位置 | 1 套轻量表现 | 平台、地面标记或装配设备出口即可；不要求新增大型机器人生产建筑 | P1 |

若 Demo 增加独立弹药机、修补件机或机器人装配机，也必须分别交付 Idle 和 Working；不能因为表中未列出就遗漏动画。

关键设备的共用状态表现：

| 状态 | 美术交付 |
|---|---|
| 正常加工 | Working 循环，按需要配合工作灯和加工特效 |
| 空闲、缺料、完成等待或堵料停工 | Idle 状态；具体原因通过 UI/状态灯区分 |
| 无电、瘫痪 | 停止工作表现，采用静止姿态；瘫痪可叠加少量烟、火花或损伤贴花 |
| 修复、重启 | 轻量修复/重启反馈；正式恢复加工后才进入 Working |
| 归属转换 | 阵营标志、局部配色或灯光变化，不需要整套敌方建筑模型 |

设备瘫痪保留布局与可识别轮廓。无需制作建筑彻底消失、大范围坍塌或每种状态一整套模型。

## 4. 加工机器动画交付与程序接入约定

### 4.1 每台机器的必交付内容

| 项目 | 要求 |
|---|---|
| Idle 空闲状态 | 可以是循环动画，也可以是完全静止的姿态；静止方案需明确指定姿态，不把“忘记绑定动画”当成静止空闲 |
| Working 工作状态 | 必须有可辨认的循环变化；按机器选择部件运动或材质/发光参数动画，不能只复制 Idle 并改名 |
| 状态命名 | 统一使用逻辑名 `Idle`、`Working`；源动画可建议命名 `<MachineKey>_Idle`、`<MachineKey>_Working`，绑定规则由导入工具确定 |
| 循环与切换 | 工作循环无明显首尾跳变；说明退出工作时回到哪个空闲姿态，以及切换是否需要短过渡 |
| 层级与枢轴 | 静态主体和活动件分开；明确活动件轴心与方向；不得用根运动移动整栋建筑 |
| 状态说明 | 附动画长度、循环方式、静止姿态、允许的过渡和附属特效/灯光说明 |
| 物流与碰撞 | 动画只改变视觉部件，不能移动网格锚点、端口地址或权威碰撞体；活动范围不应穿入玩家常用通道 |

空闲可以以静止 Clip 或显式静态姿态配置交付，具体格式在首台样机联调时确定。工作动画默认作为独立视觉循环，不要求每转一圈产出一个物品，也不通过动画事件扣料或生成产物。

### 4.2 ECS 表现层支持需求（待实现）

此需求排入 [未来计划 2 的 A07a](Future-Plan-2.md#33-a07a加工机器两态动画支持)，在第一步整体验收前完成。

- ECS 模拟决定机器是否实际推进加工；表现层据此切换 Idle/Working。只选中了配方但没有加工，不播放 Working。
- 读取现有加工状态，后续结合电力与瘫痪状态判断；停止加工后停止工作动画、工作灯及相关循环特效。
- 状态映射与动画绑定可通过现有内容导入/Baking 流程扩展。必须支持“静态 Idle + 动态 Working”，并校验工作动画缺失等错误。
- 在 `PresentationSystemGroup` 的表现更新中驱动播放；可以选用活动子实体变换或经过验证的动画适配器，具体方案结合当前模型导入链决定，不能假定导入 FBX 后 ECS 会自动播放其中动画。
- 所有播放后端遵守同一状态契约。暂停游戏时冻结播放；隐藏/重新显示后按当前模拟状态恢复，不能影响加工结果。
- 先用一台机器验证完整导入与播放，再批量制作其余机器动画，避免源文件做好后才发现层级或曲线不兼容。

装饰型建筑同样通过建筑工具交付占格与碰撞数据，但不填写加工配方和物流端口。地基材质变体沿用地基资源流程；是否需要扩展材质选择与持久化字段由建造任务确认。

- [ ] Demo 内使用的资产统一为 Low Poly 风格，现有资产已完成复用检查。
